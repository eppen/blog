要点说明

  1. AdGuard 只拦 DNS：域名解析在 OptiPlex 上过滤；实际网页/游戏数据包仍经华为路由上网。
  2. 全网生效前提：路由器 DHCP 的 DNS 服务器填 192.168.3.7，客户端重连 WiFi 后生效。
  3. 本机固定 IP：OptiPlex 已设为 192.168.3.7/24，网关 192.168.3.1。建议在路由里做 DHCP 地址保留，避免冲突。
  4. 53 端口：已关闭 systemd-resolved 的 DNSStubListener，由 AdGuard 监听 *:53。
  5. 绕过可能：客户端改用公共 DNS、DoH/DoT、代理、直连 IP 时，DNS 黑名单可能失效。

MES 计划范围文档：Excel 绿色区块解析核心

计划范围文档「导入」的关键，不是行式 CRUD 读表，而是用 Apache POI 把排产 Excel 里的装置绿色合并区拆成扁平记录 FlatRecord。实现类：ExcelGreenRegionExtractor（mes-plan）。

数据模型

每条记录对应「某装置下的一行进料或产品」：

字段 含义
processName 装置名（合并区文字，去换行）
load 负荷（合并区上方单元格，常格式化为 xx%）
capacity 加工量（合并区下方单元格）
type 进料 或 产品
itemName 物料 / 产品侧线名
amount 加工量或产量
yield 收率（仅产品）
rowNum / colNum 合并区左上角，用于排序与分组

入口：parseExcel(byte[] / File / InputStream) → XSSFWorkbook → 取第一个 Sheet → 返回按行列排序后的列表。

解析步骤

1. 以合并区为装置锚点

遍历 sheet.getMergedRegions()。合并区首格文本作为装置名；去掉 \n 后长度 < 2 或空则跳过（过滤装饰块）。当前实现里 isGreenCell 判断被注释掉，实际以「合并区 + 有意义的装置名」为准。

2. 块内相对列布局

对每个合并区调用 extractBlockData，以合并区左列为 centerCol：

  • 上方一行同列：负荷；数值则 ×100 后加 %
  • 下方一行同列：年加工量 / 备注
  • 左侧两列：进料名 + 量；过滤表头「进料」及含「合计」的行
  • 右侧三列：产品名 + 收率 + 产量；过滤「产品/侧线」及「合计」

数量、收率尽量用 BigDecimal 保留两位小数。

3. 排序

全部 FlatRecord 先按 rowNum，再按 colNum 升序，保证后续按装置分组时顺序稳定（与画布从左到右、从上到下一致）。

设计要点

  1. 结构约定优于颜色：模板用绿色合并区标装置，代码侧更依赖合并区几何与相对列偏移；颜色过滤可按需打开。
  2. 扁平化：一个装置多行进料/产品 → 多条 FlatRecord，同一 processName + 相同 load/capacity。
  3. 上游用法：JhfwDocServiceImpl.importData 读 PlanFiles 二进制调用本解析器，再按 processName 分组写入主从表；解析器本身不落库。

小结

绿色区块解析 = 合并区定装置 + 固定列偏移读进料/产品 + 上下格读负荷/加工量。改模板列布局时，优先改 extractBlockData 中的相对偏移，而不是改导入接口。

AI Daily · 2026年5月21日 · MES 工作区简报

编码 Agent 产品层加速成熟；Harness（脚手架）仍是能力放大器；检索/MCP 成为企业代码库 Agent 的基础设施。

核心摘要

  • Harness 决定上限：同一模型在不同 Harness 下表现可差近一倍（如 Gemini 3.1 Pro 17.7→31.4），说明 Cursor/规则/子 Agent 配置值得持续投入，而非只换模型。
  • 编码 Agent 从 IDE 走向跨设备运维：Codex 支持手机远程操作已锁屏 Mac、Appshots 抓取应用上下文，预示「长期在线操作员」形态，与 MES 7×24 运维场景有类比价值。
  • Agent 架构建议先单 Agent：工具/提示膨胀后再拆 Manager/子 Agent；与当前 .cursor/rules + 按需 Task 子代理的模式一致。
  • 代码库检索 + MCP 一体化：Weaviate 内置 MCP、LangChain 沙箱 Auth Proxy 与 typed streaming，指向「大单体 Java 多模块仓库」的安全 RAG 方向。
  • 开源编码模型竞争加剧：Qwen3.7-Max 在 SWE-bench 等榜单靠前，社区期待 27B/35B 开放权重；对本地/私有化辅助编码有参考意义。

与 mes-parent 直接相关

1. 继续投资「Harness」，而不是只追新模型

  • 本仓库已有 .cursor/rules、copilot-instructions.md、HTML/JS 版本规范等，本质上就是 Harness。
  • 建议：把反复出现的坑（如 var vm 勿包在 $(function(){})、@Transactional 默认 rollback、html 改 JS 必 bump 版本）沉淀进规则，效果往往大于换模型。

2. 子 Agent 用在「模块边界清晰」的任务

  • 行业共识：先单 Agent，再在工具/提示失控时拆子 Agent。
  • 适合 mes-parent：按模块并行（如 mes-plan 页面规范对齐、mes-document 接口排查），避免一个 Agent 同时改十几个 pom.xml。
  • 不适合：跨模块大重构且无明确回滚点——应先拆计划 + 小步提交。

3. MCP 与大型 Java 单体仓库

  • Weaviate 内置 MCP + 混合检索（BM25 + 向量）说明：Agent 读全仓 时检索层是产品差异化点。
  • 本工作区已启用 MySQL/MSSQL 等 MCP，可扩展模式：
    • 只读 Schema/样例查询 辅助写 Mapper/XML
    • 禁止 Agent 直接执行破坏性 SQL（配合二次确认，与现有删除按钮规范一致）

4. 编码 Agent 工作流（可借鉴到侧项目/脚本）

Reddit 高赞「十年工程师手机 Vibe Coding」要点，经筛选后适用于 非核心生产路径 的实验性开发：

实践 说明
计划模式先行 先出计划、人工收窄范围，再自动改代码
任务粒度 计划须能「装在脑子里」；过大则拆
每步 git commit 与 MES 多模块协作时的回滚习惯一致
测试与 E2E 要求 Agent 生成测试；复杂变更加安全/测试审查子步骤
明确非目标 提示中写清「不要动」的模块/文件

5. 培训资源（团队 upskill）

  • Anthropic 官方免费课程含 MCP、Claude Code、Plan Mode（anthropic.com/learn）。
  • 建议：前端/全栈同事优先 MCP + Agent 课；后端可侧重 Claude API + 企业部署路径。

工具与产品动态（节选）

Codex 产品层

  • Appshots：Mac 应用窗口截图+文本，丰富上下文。
  • 远程 Mac 操作：手机可在 Mac 锁屏时安全调用应用——长期驻场 Agent 的形态信号。
  • 团队插件共享、组织分析：企业落地编码 Agent 时的治理需求。

LangChain

  • Sandbox Auth Proxy：控制 Agent 与外界边界。
  • Typed streaming：工具/子 Agent/中断作为一等公民，而非纯 token 流——利于做「MES 操作进度 UI」类投影（若未来做内部 Agent 控制台）。

其他信号

  • mini-swe-agent 适配 ProgramBench：软件工程 Agent 的 Harness 创新仍在快速迭代。
  • turbopuffer 达 $100M ARR（检索基础设施）：上下文检索是 Agent 产品的核心战场。

模型与开源生态（节选）

  • Qwen3.7-Max：多项编码/Agent 基准靠前；开放权重 27B/35B 仍待观望。
  • **Cohere Command A+**：Apache 2.0 MoE，面向企业 Agent；社区关注 GGUF 本地部署。
  • Meta 向 Heretic 发函：Llama 衍生权重合规风险上升，选型需注意许可证链。

本周（8/31–9/4，约 74 次提交，合并 PR #384 等）主线在 计量器具台账（导入导出、附件、权限与列表体验）与 看板能力增强（书签 URL、筛选联动、透视、虚拟滚动、导出与 SQL 安全）。主力模块 mes-measure / mes-chart，另有 mes-ai、mes-utils。

一、计量器具台账（mes-measure）

  • 导入：已有设备编码增强、备注字段、导入进度与新增/更新计数
  • 导出：Excel 样式重构、状态转换、日期处理、进度条；底座导出能力同步增强
  • 台账编辑：附件上传（sys_attach）、详情按钮、表单字段行为
  • 字典：条目复制、批量取字典（sys-dict）
  • 列表与权限：列宽动态调整、菜单权限与单位选择 UI、jqGrid 行数与布局细节

二、看板 / Chart（#384）

  • 能力：书签 URL、筛选联动、透视、虚拟滚动、DBMON 缓存
  • 导出：看板导出与数值导出；表头渲染增强
  • 安全：SQL 校验由 JSqlParser 切到 Druid；前导分号校验
  • Demo：DEMO_CAPABILITY_BOARD 演示新能力；组件高度与布局微调

三、AI 与装置开停工（mes-ai）

  • 装置开停工区间表与年份日期解析
  • Agent 绑定 SQL/Java 调整；联锁使用汇总查询优化
  • 能耗图 SQL 去掉冗余能源类型过滤

四、运行监控、配置与位号

  • Tomcat 运行状态监控与可视化增强（mes-utils-runtime-monitor）
  • 系统配置变更事件发布与资源管理重构
  • 位号（fm）数据源筛选与 UI；调度页操作栏布局

五、其它平台项

  • 容器作业 / 报表模板：jqGrid 默认页大小统一为 30；UI 与提示方式调整
  • 菜单与 EOS Tree 同步；文档侧更新 2026 H2 计划与 Spring Boot 3 迁移计划

2026-08-31

MES 2026 年第 35 周工作小结

本周（8/24–8/29，约 85 次提交，合并 PR #174、**#382** 等）主线在 壳层导航体验（全局搜索、侧栏、模块 Tab）、LIMS 数据源与位号对接、本地 bge-m3 embedding，以及工作台到期提醒与 EOS 权限移除。主力模块 mes-web / mes-visual / mes-factory / mes-ai。

一、壳层导航与全局搜索（#174）

  • 全局菜单搜索：组件布局、响应式样式与状态管理；z-index 与下拉交互
  • 侧栏：折叠态展示、滚动行为、本地过滤；菜单加载后再初始化路由
  • 模块 Tab / 导航栏：Tab 布局与样式、打开方式项；页脚版权年份动态化
  • 角色详情页布局可读性调整

二、LIMS 数据源与位号

  • LIMS 数据源配置：RDB SQL 数据源实现；精度保留；sys_config value 扩至 4000
  • 结果数据：筛选排序、网格配置与菜单 SQL
  • 位号（fm）：导入下载对接 LIMS；采集流程与样式收敛
  • 数据源配置页 JSON 编辑器

三、AI embedding 与知识库

  • 默认改用本地 bge-m3 embedding（免 API Key）；Docker 环境配置同步
  • 知识库 测试检索 能力与 UI
  • 当前时间预调用（系统消息前置合并）；SQL 工具参数解析增强

四、工作台、到期提醒与容器

  • 首页 badge 接口与工作台快照/超时处理
  • 到期提醒：状态判定、聚合调度、复制；工作台提醒汇总
  • 容器工作台 providers 与状态计数；任务组参数加载
  • 首页提示统一为 msg / alert

五、工艺可视化、过程控制与安全

  • P&ID：集成 draw.io Stencils、ISA 符号管理；SVG 描边与样式归一
  • 过程控制（#382）：超限异常记录时长计算与写入
  • EOS 权限：角色权限「移除授权」模式；清理孤立空目录
  • Docker 本地直连端口映射、Flowable schema 自动升级等开发便利项

一句话：本周以壳层导航与全局搜索落地为主，LIMS 数据源/位号与本地 embedding 并进，工作台到期提醒与 P&ID 图元、EOS 权限移除补齐平台与安全侧能力。

2026-08-25

MES 2026 年 8 月工作小结

8 月（截至 8/25，约 320 次提交、合并 PR #360 / #368–#381，另有多条功能分支直接合入）主线是把 mes-ai 从「能出表/图」推进到 配方化 SQL 查询、双区间对比与 AgentScope 子运行时，并同步加深看板下钻、工艺符号面板与 EOS 权限移除能力。改动最集中的模块是 mes-ai，其次 mes-chart / mes-web / mes-visual / mes-security；月末打上 release-2026-08-25。

一、MES-AI：sql_compose、双区间图与 AgentScope

  • sql_compose：配方化查询生成、别名/LIKE/单位校验、产耗默认负号、双区间对比图与 [区间1]/[区间2] 列标签；「回溯起算」日期解析与 TOP/CTE 安全注入。
  • AgentScope：新增 mes-agentscope 子模块，子 Agent 配置、权限模式、表格块与图表抽取、token usage 写入运行日志；管理端与协作编排联动。
  • 对话体验：Markdown/语法高亮、思考步骤、会话搜索与历史内嵌图表、运行日志反馈/复测、相对月份 SQL 参数、选项回答与工具移交编辑。
  • 能耗工具链：日表多装置、同比环比/趋势/饼图、存储过程工具出图、excludeFromUiTable、列组与汇总行、多日均值查询、当前时间预调用。

二、看板与可视化

  • 下钻：饼图/柱图弹层明细 → 行级二级详情；能耗模块明细 SQL 与多看板下钻文档补齐；多柱图支持。
  • 嵌套饼图：色相微调、固定品类配色、零值过滤与高亮；看板树展开、月份筛选与图表包导入导出。
  • 工艺工程：ISA 5.1 仪表符号面板、P&ID 工艺符号面板与生成脚本；设计图/图形资产页交互规范。
  • 项目甘特：可拖拽分栏、布局与基线/排程相关增强（mes-project）。

三、权限安全与其它业务

  • EOS：角色权限移除授权模式、孤立目录剪枝、菜单树拖拽重排、角色管理 UI 与菜单详情刷新交互。
  • 船舶 / 工作台：码头船舶待办 Provider；联锁强制投用率相关查询。
  • 计量：恒值监测状态持久化与告警联动、仪表型号管理、监测规则按电表批量查询。
  • 基础设施：Docker 本地直连端口映射、Flowable schema 自动升级；UI 查询区对齐与成功 msg/失败 alert 规范落地。

四、月度节奏

阶段 重点
上旬 协作子 Agent / 工具移交、相对月份参数、运行日志反馈复测、对话内图表合入（#360）
中旬 存储过程出图、能耗趋势/饼图/同比、嵌套饼与下钻、Eos 菜单拖拽与权限修复（#376–#381）
下旬 sql_compose 与双区间图、AgentScope、看板二级下钻、P&ID 符号面板、EOS 移除授权；发版 release-2026-08-25

一句话：8 月把 MES-AI 推到「能配方写 SQL、能双区间出图、能挂 AgentScope」，看板下钻与工艺符号面板同步成型，并在月末完成 release-2026-08-25 发版收口。

2026-08-15

MES 2026 年第 33 周工作小结

本周（8/8–8/15，活跃提交 8/11–8/14，约 74 次提交、合并 PR #376–#381）主线在 AI 能耗分析图表能力（存储过程出图、趋势/饼图、同比环比），同步推进看板嵌套饼图与下钻、联锁强制投用，以及 Eos 菜单拖拽与权限修复。主力模块 mes-ai（约 141 文件触达），次为 mes-chart（约 70 文件）。

一、AI 存储过程图表与能耗分析（#378、#379、#381）

把能耗类 SQL 工具从「表格结果」推进到「对话内可渲染图表」：

  • 存储过程工具支持图表输出：SqlToolChartBuilder 增强 tooltip、系列类型与默认配色同步；能耗分析工具补充 chart intent 与月份处理
  • 能耗趋势：多线图、单位过滤、趋势查询与标签修正；去掉不适用的 exclusive_group
  • 能耗饼图 / 统计图：嵌套饼、RATE 展示对齐图形查询路由；柱状图顶部数值展示；图表快照导出 snapshotChartsToImages
  • 同比 / 环比：能耗分析存储过程增强 MoM/YoY、按消耗类型细化；excludeFromUiTable 与 remarks 收敛；修复同比列缺失与单位后缀（#380）

二、智能体会话与聊天体验（#377）

  • 会话历史检索增强，运行日志详情内嵌图表渲染
  • 会话搜索、等待态指示、图表 resize
  • 适配 deepseek-v4-flash；SQL JSON 输出保留 NULL；列可见性策略补充空内容与行去重
  • 聊天表格 / Agent 卡片样式与布局修复；运行日志列表性能相关合入

三、看板 chart：嵌套饼图与交互

  • 嵌套饼图配置、绑定与零值过滤；动态系列类型与饼图坐标轴清理
  • 能耗图表下钻、高亮；看板菜单树展开/折叠
  • 图表包导入导出；画布高度计算修复

四、联锁强制投用与权限安全（#376）

  • 联锁监控纳入 isForce（强制投用）条件与查询方法
  • Eos 菜单树支持拖拽重排；菜单缓存防误改
  • 权限批量删除处理重构修复

五、其它

  • 容器运行图表配色同步
  • 审批组面板样式调整
  • 清理 /rtdb/pi 相关废弃存储过程与函数
  • H2 任务计划与 code review 文档更新

一句话：本周以 AI 能耗存储过程出图与同比环比分析落地为主，看板嵌套饼图/下钻跟上，联锁强制投用与 Eos 菜单拖拽补齐平台侧能力。
