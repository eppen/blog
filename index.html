AI Daily · 2026年5月21日 · MES 工作区简报

编码 Agent 产品层加速成熟；Harness（脚手架）仍是能力放大器；检索/MCP 成为企业代码库 Agent 的基础设施。

核心摘要

  • Harness 决定上限：同一模型在不同 Harness 下表现可差近一倍（如 Gemini 3.1 Pro 17.7→31.4），说明 Cursor/规则/子 Agent 配置值得持续投入，而非只换模型。
  • 编码 Agent 从 IDE 走向跨设备运维：Codex 支持手机远程操作已锁屏 Mac、Appshots 抓取应用上下文，预示「长期在线操作员」形态，与 MES 7×24 运维场景有类比价值。
  • Agent 架构建议先单 Agent：工具/提示膨胀后再拆 Manager/子 Agent；与当前 .cursor/rules + 按需 Task 子代理的模式一致。
  • 代码库检索 + MCP 一体化：Weaviate 内置 MCP、LangChain 沙箱 Auth Proxy 与 typed streaming，指向「大单体 Java 多模块仓库」的安全 RAG 方向。
  • 开源编码模型竞争加剧：Qwen3.7-Max 在 SWE-bench 等榜单靠前，社区期待 27B/35B 开放权重；对本地/私有化辅助编码有参考意义。

与 mes-parent 直接相关

1. 继续投资「Harness」，而不是只追新模型

  • 本仓库已有 .cursor/rules、copilot-instructions.md、HTML/JS 版本规范等，本质上就是 Harness。
  • 建议：把反复出现的坑（如 var vm 勿包在 $(function(){})、@Transactional 默认 rollback、html 改 JS 必 bump 版本）沉淀进规则，效果往往大于换模型。

2. 子 Agent 用在「模块边界清晰」的任务

  • 行业共识：先单 Agent，再在工具/提示失控时拆子 Agent。
  • 适合 mes-parent：按模块并行（如 mes-plan 页面规范对齐、mes-document 接口排查），避免一个 Agent 同时改十几个 pom.xml。
  • 不适合：跨模块大重构且无明确回滚点——应先拆计划 + 小步提交。

3. MCP 与大型 Java 单体仓库

  • Weaviate 内置 MCP + 混合检索（BM25 + 向量）说明：Agent 读全仓 时检索层是产品差异化点。
  • 本工作区已启用 MySQL/MSSQL 等 MCP，可扩展模式：
    • 只读 Schema/样例查询 辅助写 Mapper/XML
    • 禁止 Agent 直接执行破坏性 SQL（配合二次确认，与现有删除按钮规范一致）

4. 编码 Agent 工作流（可借鉴到侧项目/脚本）

Reddit 高赞「十年工程师手机 Vibe Coding」要点，经筛选后适用于 非核心生产路径 的实验性开发：

实践 说明
计划模式先行 先出计划、人工收窄范围，再自动改代码
任务粒度 计划须能「装在脑子里」；过大则拆
每步 git commit 与 MES 多模块协作时的回滚习惯一致
测试与 E2E 要求 Agent 生成测试；复杂变更加安全/测试审查子步骤
明确非目标 提示中写清「不要动」的模块/文件

5. 培训资源（团队 upskill）

  • Anthropic 官方免费课程含 MCP、Claude Code、Plan Mode（anthropic.com/learn）。
  • 建议：前端/全栈同事优先 MCP + Agent 课；后端可侧重 Claude API + 企业部署路径。

工具与产品动态（节选）

Codex 产品层

  • Appshots：Mac 应用窗口截图+文本，丰富上下文。
  • 远程 Mac 操作：手机可在 Mac 锁屏时安全调用应用——长期驻场 Agent 的形态信号。
  • 团队插件共享、组织分析：企业落地编码 Agent 时的治理需求。

LangChain

  • Sandbox Auth Proxy：控制 Agent 与外界边界。
  • Typed streaming：工具/子 Agent/中断作为一等公民，而非纯 token 流——利于做「MES 操作进度 UI」类投影（若未来做内部 Agent 控制台）。

其他信号

  • mini-swe-agent 适配 ProgramBench：软件工程 Agent 的 Harness 创新仍在快速迭代。
  • turbopuffer 达 $100M ARR（检索基础设施）：上下文检索是 Agent 产品的核心战场。

模型与开源生态（节选）

  • Qwen3.7-Max：多项编码/Agent 基准靠前；开放权重 27B/35B 仍待观望。
  • **Cohere Command A+**：Apache 2.0 MoE，面向企业 Agent；社区关注 GGUF 本地部署。
  • Meta 向 Heretic 发函：Llama 衍生权重合规风险上升，选型需注意许可证链。

MES 2026 年 5 月工作小结

5 月（约 220+ 次提交、合并 PR #239–#281）主线落在业务现场能力：交接班 Docx 模型导入、液体码头/船舶作业增强、仪表位号与报表关联，以及 RTDB/ISYS 采集链路。改动最集中的是 mes-operation、mes-measure、mes-vessel-operation，辅以 mes-web / mes-rtdb。

一、交接班 ShiftLog（中下旬主线）

  • Docx 模型导入与解析预览（#263）：锚点注入、单元格模式、输入类型与公式处理。
  • 跳过孤儿锚点（#270）、批量删除与归属校验、调度日志预览。
  • Docx 解析器持续增强（#278）：条目类型、标签推断、TABLE_STR_BC 批量生成等。
  • 月末补齐 docx_code 唯一性校验（#281）。

二、船舶 / 液体码头作业

  • 内外贸字段、管线名称、货种筛选与泊位告警（#239/#241/#246/#248）。
  • 收发油罐按物料多选（#244）；船名模糊检索等终端体验。
  • 船舶动态导入：到港时间格式与提示信息修复（#258/#276）。
  • 排船页接入真实 LLM 辅助（#275）。

三、仪表位号与报表

  • 手动采集按钮（#254）；位号配置、导入导出、唯一性与时间处理（#267）。
  • 关联报表模板展示与批量查询、模板维度（#252/#265）。
  • 报表/位号侧过滤与 jqGrid 行范围选择。

四、实时库与工程体验

  • RTDB ISYS SDK RMI 回调（#271）；ISYS 配置与 HTTP 客户端增强。
  • SpringDoc OpenAPI / Swagger UI 接入。
  • 多 Tab 溢出箭头滚动（#273）、滚动条样式、模态间菜单切换；菜单关键词逗号 OR 搜索（#269）。
  • 反馈排程关闭/驳回态隐藏按钮等细节（#250）。

五、月度节奏

阶段 重点
上旬 液体码头罐/管线/货种、位号手动采集、报表模板维度
中旬 交接班 Docx 导入起步、位号关联报表、菜单搜索与 UI 修复
下旬 ShiftLog 解析深化、RTDB RMI、排船 AI、到港时间导入、docx 唯一性

一句话：5 月把交接班 Docx 导入做成可用链路，并加强液体码头作业与仪表采集/报表关联；实时库回调与若干前端体验同步落地，为 6 月平台化（AI/能耗/图表）腾出业务底座。

MES 2026 年 6 月工作小结

6 月（约 340+ 次提交、合并 PR #277–#310）是平台能力铺开的一个月：落地 mes-ai Agent 平台 与 mes-energy 模块，图表看板与 AI 向导增强，并同步推进 Eos 权限、OTP、在线消息与个人工作台。改动较均衡地落在 mes-core / mes-web / mes-ai / mes-energy / mes-chart。

一、MES-AI Agent 平台（下旬主线，#305）

  • 新增 mes-ai 模块骨架：Agent 管理、聊天流式输出、thinking 步骤跟踪。
  • SQL 工具执行与表格流式渲染、能耗 Agent SQL/输出格式迭代。
  • Schema Tool、菜单权限与助手推荐问题/欢迎语等体验补齐。

二、能耗模块 mes-energy（中下旬）

  • 独立 mes-energy 并接入 web 依赖；峰谷（TOU）时段配置、日统计、分页/汇总/导出。
  • 电表数据源管理、手动录入、相邻时段合并、能耗看板菜单与电压等级过滤等。

三、图表看板与 AI 向导（#304）

  • 看板设计：布局预设、槽位、组件面板、主题与最大化查看。
  • SQL 编辑（CodeMirror）、安全校验与试跑；AI 配置/SQL 审查、图层面板主题说明。

四、权限、认证与消息

  • Eos 角色管理（#299）：对象级权限配置、菜单同步、权限详情与 UI 重构。
  • OTP 二期（#289/#294）；runas 用户切换修复（#277）；权限 token 切换（#309）。
  • 在线消息通知（#307）与列表慢查询优化（#308）；系统菜单导航慢查询（#306）。

五、其它业务与工程

  • 个人工作台（#310）；首页用户下拉菜单（#295）。
  • 储罐体积/导入导出（#298）；班组装置同步（#302）；交接班 shiftlog（#286/#287）。
  • Flowable/请假流程与 Docker 配置；jqGrid 多表头紧凑样式；mes-core 单测补强。
  • SysLog 注解与敏感字段、QRTZ/监控相关增强。

六、月度节奏

阶段 重点
上旬 runas/OTP、交接班、jqGrid、mes-core 测试、反馈看板
中旬 Eos 角色权限、储罐体积、图表看板设计、mes-energy / mes-ai 起步
下旬 AI Agent 平台合入、图表 AI 向导、能耗 TOU、消息与慢查询、个人工作台

一句话：6 月搭好了 AI Agent、能耗与图表看板三块新底座，并在 Eos 权限与登录安全上完成一轮可用交付，为 7 月能耗智能体与生产运行闭环打基础。

MES 2026 年 7 月工作小结

7 月（约 400+ 次提交、合并 PR #312–#367）主线是把 mes-ai 从可用原型推进到能耗/生产运行可落地，并顺带补齐权限、调度、图表与安全。改动最集中的模块是 mes-ai，其次 mes-web / mes-security / mes-chart。

一、MES-AI 平台能力（全月主线）

  • 多 Agent / 路由：协作 MVP、首页浮动助手接入 mes_router、窗口最大化、会话与统计增强。
  • 工具调用（FC/ReAct）：空工具调用恢复与 nudge、互斥意图、few-shot / handler_config 常见错误提示、同参重复调用治理、运行日志可观测与重试。
  • SQL 工具链：参数槽位抽取、日期区间（含半月）、列标签/排序、存储过程工具、结果图表与表格渲染（列组、着色、汇总行、excludeFromUiTable）。
  • 模型与配置：thinking 模式、采样参数、工具业务分类、硬编码治理（默认模型可配置等）。
  • 管理端：工具/Agent 列表与编辑、级联删除、聊天停止、用户改消息、反馈/复测标记、页面规范（按钮/msg）。

二、业务智能体落地

  • 能耗分析：同比环比、日表多装置查询、Z_View_NHFX_*、列显隐与意图策略、图表双轴等多轮打磨。
  • 生产运行 / 工程师日志：填报状态意图与工具互斥、工程师/部门长问题频次与运行日志查询工具；月末落地 Eos 工程师日志 定时提交模块（#366）。
  • 生产运行 FC 智能体（#324）及相关 SQL/提示持续迭代。

三、权限与安全

  • Eos 角色对象权限、单权限替换模式、eosrole 一次完成 EOS+MES 用户授权。
  • JSON 请求加密、XSS 过滤与 AI/Chart 定点抽检。
  • mes-chart 安全与可维护性改造。

四、基础设施与其它业务

  • Quartz：P0/P1/P2 工程化、超时控制、失败告警、任务日志状态。
  • 工作台 P0–P2（#327）。
  • 船舶：vesselOperationDynamicId 终端强制/校验。
  • Excel/JXLS、用户导出、在线消息详情、jqGrid 全局错误处理、本地 LLM profile 等。

五、月度节奏

阶段 重点
上旬 Eos 权限、本地 LLM、AI 管理端基础、聊天停止、生产运行 FC
中旬 运行可观测、意图互斥、槽位抽取、加密/XSS、协作与图表
下旬 多 Agent 路由入口、Quartz、能耗 SQL/表格体系、工程师日志模块、硬编码治理

一句话：7 月把 MES-AI 做成「能路由、能调工具、能出表/图、能追日志」的平台，并在能耗分析与生产运行上形成可演示的业务闭环；权限、调度、图表安全同步加固。

MES 本周工作小结（2026-07-28 ~ 08-01）

本周（7/28–8/1）工作以 MES-AI 能耗分析与对话表格展示 为主线，并落地了 Eos 工程师日志、船舶作业校验与一批文档。约 74 次提交，合并 10 个 PR（#357–#367）。

一、MES-AI 能耗智能体（主线）

  • SQL 工具与参数：完善能耗工具参数解析（#357）、同比环比工具、装置/时段槽位提取；多轮按运行日志纠偏（装置识别、明细 vs 汇总、单位标注等）。
  • 日表查询：新增 energy_nhfx_day / Z_View_NHFX_TABLE 日表多装置查询（#363），持续修 JSON、错误处理与设计物耗字段表述。
  • 表格与图表：复合表头/列组（#358）、单元格着色（#359）、汇总行与派生率（#361）、双图（多日/多装置）、excludeFromUiTable 隐藏辅助结果（#365）。
  • 稳定性：StoredProcToolHandler 围绕 Fastjson 未闭合字符串等问题迭代，后简化控制字符预处理逻辑。
  • 硬编码治理：默认模型可配置、Embedding base-url 清理等 P0 项合入（#367）。

二、AI 管理端与规范

  • AI 列表/编辑页统一按钮样式、导航、成功提示改用 msg（#364）。
  • Cursor 规则与页面约定对齐（成功/失败提示、按钮风格）。

三、Eos / 安全任务

  • 新增 Eos 工程师日志 模块（OpenService 客户端、定时任务、装置配置、测试）（#366）。
  • 日常用 skill/脚本按 token 批量生成各装置工程师日志。
  • 补充/更新 EOS 角色-菜单、角色树 nodeId/objectId 文档。

四、船舶作业

  • 终端侧强制/校验 vesselOperationDynamicId（#362）。
  • 完善到离港接口与 mes-measure-vessel ↔ mes-vessel-operation 调用说明文档。

五、其他

  • mesdata 存储过程/函数梳理、能耗模型数据核对、日志错误报告更新。
  • README 与若干 AI/业务 PDF 文档整理。

六、周末进行中

本地仍有未合入改动：ai-chat-render.js、若干 AI HTML，以及 index.html / main.css（偏首页/样式微调）。

一句话：本周把能耗 AI 从「能查」推进到「表格好看、图表可用、结果可控、配置可治理」，并完成工程师日志自动化与船舶动态 ID 校验。
