采购订单（注文书）系统：从订单生成到到货验收的电子化流程

发表于2026-10-24|更新于2026-10-24|产品介绍
|浏览量:

日本語版はこちら → 購買注文書システムの業務フロー（日本語版）

本文整理自某制造企业内部的采购订单系统实施过程，实际系统名以 POFlow 指代。

一句话定位：POFlow 采购订单模块是 TPICS 系统的一个 Web 扩展（addon），它把采购订单（注文书）从「生成 → 确认 → 审批 → 打印/发送 → 到货验收」的整个业务链条做成了电子化流程，替代了过去的纸质流转。

1. 背景与定位

  • POFlow 是什么：一个独立的 Web 应用，在技术上是 TPICS 系统的「外挂扩展」，与 TPICS 共用同一套业务数据库，登录账号和权限也复用 TPICS 的安全体系——业务人员无需另行开账号。
  • 模块不「新建」订单：采购订单由 TPICS 中的 MRP（物料需求计划）自动生成。本模块负责这些订单的后续处理：确认、审批、打印、发送和到货验收，而不是从零创建订单。

整个模块在系统内实际由三个相互衔接的功能组成一个整体：采购订单审批、打印订单与纳品书、到货验收。

1.1 系统定位图

flowchart LR
    MRP["TPICS · MRP<br/>物料需求计划"] -->|自动生成采购订单| MW["POFlow<br/>采购订单模块"]
    SEC["TPICS · 安全体系<br/>账号 / 权限"] -.->|登录与权限复用| MW
    MW <-->|读写同一套业务数据| DB[("TPICS 业务数据库<br/>（共用）")]
    MW -->|PDF 邮件| VN["厂家（供应商）"]

要点：本模块不创建订单，订单由 MRP 生成；模块只负责订单的确认 → 审批 → 打印/发送 → 验收这段后续业务。

2. 核心功能

功能 说明
采购订单审批 订单经多级确认后提交上级审批，支持通过 / 拒绝 / 取消；系统按订单金额自动分配审批人。
打印订单与纳品书 审批通过后生成 PDF，可加盖审批人数字签名；订单与纳品书（交货单）可邮件发送给厂家。
到货验收 货物到货后录入「受入」数量，与订单核对「检收」；超期未检收自动标红提醒；未结清部分可打印「残传票」。

  1. 确认阶段：采购订单先在采购组（調達グループ）确认，再到需给组（需給グループ）确认（可补充备注、标记删除），最后由采购组再次确认并提交审批。
  2. 审批阶段：上级（上长）审批。通过则进入打印/发送；拒绝则退回重新确认（需说明拒绝理由）；也可在提交后、审批前取消申请。
  3. 打印/发送阶段：审批通过后，订单与纳品书生成为 PDF 并由审批人数字签名，再通过邮件发送给对应厂家。
  4. 验收阶段：货物到货后录入受入数量，与订单进行检收核对；受入后超过 3 个工作日仍未检收的记录会标红提醒；尚未结清的订单可打印「残传票」继续追踪。

3.2 审批状态流转

    待提交审批 --> 审批中 : 提交上级审批

    审批中 --> 已通过 : 审批通过
    审批中 --> 被拒绝 : 审批拒绝（需填写理由）
    审批中 --> 已取消 : 提交后、审批前取消申请

    被拒绝 --> 待确认 : 退回重新确认

    已通过 --> 已发送 : 订单 / 纳品书邮件发送厂家
    已通过 --> 已通过 : 打印 PDF + 数字签名

    已发送 --> [*]
    已取消 --> [*]
状态 含义
待确认 订单等待采购组确认（或需给组确认）
待提交审批 已确认完毕，等待提交上级
审批中 已提交，上级审批中
被拒绝 审批不通过，需退回重新确认
已通过 审批通过，可打印、发送厂家
已发送 订单与纳品书已邮件发送给厂家
已取消 提交后在审批前被申请人取消

4. 角色与职责

角色 职责
采购组（調達グループ） 首轮确认与最终再确认，提交审批
需给组（需給グループ） 中间确认，补充备注、标记删除
上级（上长 / 审批人） 审批通过、拒绝或取消；数字签名
厂家（供应商） 接收系统邮件发送的订单与纳品书

5. 支持的订单类型

类型 说明
MRP 订单（PO） 由 MRP 自动生成的常规采购订单
手做订单（HD） 手工录入的订单
设计订单（SJ） 设计部门（设计课）的订单
破坏品订单（BP） 破坏性部品/破坏品订单

6. 价值小结

  • 全程电子化、可追溯：每一步确认、审批、打印、发送都留有记录，替代纸质流转。
  • 审批留痕 + 数字签名：审批结果与签名电子化存档，权责清晰。
  • 自动通知：提交、审批结果、发厂家均通过邮件自动通知相关人。
  • 验收把关：到货数量与订单核对，超期未检收自动提醒，避免漏检。
