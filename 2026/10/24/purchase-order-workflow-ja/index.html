購買注文書システムの業務フロー：注文書生成から入荷検収までの電子化

发表于2026-10-24|更新于2026-10-24|产品介绍
|浏览量:

中文版はこちら → 采购订单（注文书）系统：从订单生成到到货验收的电子化流程

本文は、ある製造企業における購買注文システムの導入過程を整理したものです。実際のシステム名は POFlow（ピーオーフロー） で表しています。

一言で言えば：POFlow の購買注文書モジュールは、TPICS システムの Web 拡張（アドオン）です。購買注文書（注文書）の「生成 → 確認 → 承認 → 印刷/送信 → 入荷検収」という一連の業務を電子化し、従来の紙による運用を置き換えます。

1. 背景と位置づけ

  • POFlow とは：独立した Web アプリケーションで、技術的には TPICS システムの「外部拡張（アドオン）」です。TPICS と同じ業務データベースを共有し、ログインアカウントと権限も TPICS のセキュリティ体系を再利用するため、業務担当者は新たにアカウントを作る必要がありません。
  • モジュールは注文書を新規作成しない：購買注文書は TPICS の MRP（所要量計画）によって自動生成されます。本モジュールはその注文書の後続処理（確認・承認・印刷・送信・入荷検収）を担い、ゼロから注文書を作成するものではありません。

モジュール全体は、システム上では相互に連携する 3 つの機能が一体となって構成されています：購買注文書の承認、注文書と納品書の印刷、入荷検収。

1.1 システム位置づけ図

flowchart LR
    MRP["TPICS · MRP<br/>所要量計画"] -->|購買注文書を自動生成| MW["POFlow<br/>購買注文書モジュール"]
    SEC["TPICS · セキュリティ体系<br/>アカウント / 権限"] -.->|ログイン・権限を再利用| MW
    MW <-->|同一の業務データを読み書き| DB[("TPICS 業務データベース<br/>（共有）")]
    MW -->|PDF をメール送信| VN["メーカー（仕入先）"]

ポイント：本モジュールは注文書を新規作成しません。注文書は MRP が生成し、モジュールは確認 → 承認 → 印刷/送信 → 検収という後続業務のみを担います。

2. 主な機能

機能 説明
購買注文書の承認 注文書を複数段階の確認を経て上長へ承認申請。承認 / 却下 / 取消に対応。システムが注文金額に応じて承認者を自動割り当て。
注文書と納品書の印刷 承認後に PDF を生成し、承認者の電子署名を付与可能。注文書と納品書をメーカーへメール送信可能。
入荷検収 入荷時に「受入」数量を入力し、注文書と「検収」を照合。期限内に検収されない場合は自動で赤字表示。未完了分は「残伝票」を印刷可能。

3. 業務フロー

3.1 全体業務フロー図

  1. 確認段階：購買注文書はまず調達グループで確認され、次に需給グループで確認（備考の追記・削除フラグの付与が可能）、最後に調達グループが再確認して承認申請します。
  2. 承認段階：上長が承認します。承認なら印刷/送信へ進み、却下なら再確認へ差し戻します（却下理由の記入が必要）。申請後・承認前に取消することも可能です。
  3. 印刷/送信段階：承認後、注文書と納品書が PDF として生成され、承認者の電子署名が付与されたうえで、該当メーカーへメール送信されます。
  4. 検収段階：入荷時に受入数量を入力し、注文書と検収照合を行います。受入後3 営業日を超えても検収されていない記録は赤字表示されます。未完了の注文書は「残伝票」を印刷して追跡を続けられます。

3.2 承認ステータスの遷移

stateDiagram-v2
    [*] --> 確認待ち

    確認待ち --> 承認申請待ち : 調達 step1 → 需給 step2 → 調達 step3 確認完了
    承認申請待ち --> 承認中 : 上長へ申請
    承認中 --> 承認済み : 承認
    承認中 --> 却下 : 却下（理由の記入が必要）
    承認中 --> 取消済み : 申請後・承認前の取消

    却下 --> 確認待ち : 再確認へ差し戻し

    承認済み --> 送信済み : 注文書 / 納品書をメーカーへメール送信
    承認済み --> 承認済み : PDF 印刷 + 電子署名

    送信済み --> [*]
    取消済み --> [*]
ステータス 意味
確認待ち 注文書が調達グループ（または需給グループ）の確認待ち
承認申請待ち 確認完了、上長への申請待ち
承認中 申請済み、上長の承認待ち
却下 承認不成立、再確認へ差し戻し
承認済み 承認成立、印刷・メーカー送信が可能
送信済み 注文書と納品書をメーカーへメール送信済み
取消済み 申請後・承認前に申請者が取り消した状態

3.3 役割シーケンス図（承認 → 印刷 → 送信）

sequenceDiagram
    autonumber
    actor T as 調達グループ
    actor J as 需給グループ
    actor U as 上長（承認者）
    participant M as POFlow
    participant V as メーカー

    T->>M: 注文書を確認（step1）
    J->>M: 注文書を確認 + 備考 / 削除フラグ（step2）
    T->>M: 再確認して承認申請（step3）
    M->>U: 承認待ちをメール通知
    U->>M: 承認 / 却下 / 取消
    alt 承認
        M->>M: PDF 生成 + 電子署名
        M->>V: 注文書 + 納品書をメール送信
        M->>T: 承認結果をメール通知
    else 却下
        M->>T: 再確認へ差し戻し（却下理由を通知）
    else 取消
        M->>T: 申請取消、フロー終了
    end

4. 役割と責務

役割 責務
調達グループ 初回確認と最終再確認、承認申請
需給グループ 中間確認、備考追記・削除フラグ付与
上長（承認者） 承認・却下・取消、電子署名
メーカー（仕入先） システムからメール送信された注文書・納品書の受領

5. 対応する注文書種別

種別 説明
MRP 注文（PO） MRP により自動生成された通常の購買注文書
手書き注文（HD） 手入力で作成された注文書
設計注文（SJ） 設計部門（設計課）の注文書
破壊品注文（BP） 破壊部品／破壊品の注文書

6. 導入効果のまとめ

  • 全工程の電子化・トレーサビリティ：確認・承認・印刷・送信の各ステップが記録され、紙の運用を置き換えます。
  • 承認の記録と電子署名：承認結果と署名を電子的に保管し、責任の所在が明確になります。
  • 自動通知：申請・承認結果・メーカー送信をメールで関係者へ自動通知します。
  • 検収の管理：入荷数量と注文書を照合し、期限内未検収を自動で注意喚起して検収漏れを防ぎます。
