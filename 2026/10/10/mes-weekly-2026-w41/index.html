MES 2026 年第 41 周工作小结

本周（10/6–10/10，master 约 18 次提交）主线是 PI API（piapi64）Java 封装 与 实时库通讯完整性（Comm Int），并顺带统一 Jackson 时间格式、清理 IO 模型与本地开发文档。合入分支：copilot/add-java-wrapper-for-piapi64、feature/rtdb-comm-int。主力模块 mes-rtdb、mes-factory、mes-process-*。

一、PI API / piapi64 Java 封装（mes-rtdb-pi）

  • 合入 copilot/add-java-wrapper-for-piapi64：JNA 对接 piapi64 原生库，经 RMI 对外提供快照等能力（mes-rtdb-pi / mes-rtdb-pi-core）
  • 封装 pisn_getsnapshots 批量读快照；完善快照取数错误处理
  • 支持 字符串点（string points）；补充 PI C API 参考与库加载测试文档

二、实时库通讯完整性 Comm Int（mes-rtdb / process）

  • 合入 feature/rtdb-comm-int：工艺卡 / 自控 / 联锁侧通讯完整性实体、服务、任务与前端列表页
  • 数据源侧增强 质量位校验 与空值处理；新增 RtdbMissTracker 及单测
  • 配套 SQL：doc/sql/process_rtdb_comm_int.sql

三、IO 模型整理（InstrumentResult / Parameter）

  • InstrumentResult：补文档、收敛旧方法并标废弃，配合数据源改造
  • InstrumentParameter：清理无用字段与注释

四、平台与文档杂项

  • 多子应用补齐 spring.jackson 时间格式；SysRole / SysUser 等实体 createTime 显式 JSON 格式
  • Docx 模板 sortOrder 处理修正
  • 本地开发：STS / Nginx 文档整理、/mes/ location 说明；API Key 占位改为 local-no-key；去掉无用 hc4j-intf 依赖

节奏

时段 侧重
周三 PI wrapper 与 Comm Int 合入；Jackson / Docx / 本地文档
周四 批量快照、字符串点、PI 文档与 Instrument 清理
周五 InstrumentResult 文档化与废弃收敛

一句话：把 PI 原生能力接到 Java RMI 链路上，同时把工艺侧实时库「通讯是否断了」做成可查的 Comm Int 能力。
