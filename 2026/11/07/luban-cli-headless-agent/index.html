认识 Luban CLI：把编码 Agent 搬进终端

发表于2026-11-07|更新于2026-11-10
|浏览量:

上一篇聊了嵌在 VSCodium 侧边栏里的 Luban。这一篇说它的另一副面孔：**luban 命令行**。

同一个包 @luban-code/luban-code，除了扩展，还带了一个 bin：不启动编辑器，直接把 agent 的工具循环跑在终端里。SSH 到服务器、写脚本、挂 CI、定时任务，这些场景下没有侧边栏，但「说一句话，它改文件、跑命令、自己验证」这件事照样成立。

为什么还要一个 CLI

侧边栏面板很好用，但它有两个前提：你得开着图形界面，而且得在编辑器里。

CLI 补的正是这两块空白：

  • 远程 / 无 GUI：SSH 上去只有一个 shell，也能让 agent 干活；
  • 可脚本化：一条命令跑完就退出，能接管道、能进 cron、能塞进 Makefile；
  • 同一套能力：CLI 不是另写一个简化版，而是把扩展里的 runAgent / execTool / 工具集原样复用——工具循环、只读闸门、子代理、MCP、审计都在里面。

实现上有点意思：它 stub 掉 vscode 模块后直接 require 扩展源码，等于给同一颗大脑换了个躯壳。所以你在面板里熟悉的 search_code、apply_patch、run_command、read_spill，在终端里行为一致。

安装与配置

两个和面板不同的点，值得提前知道：

  1. key 只认文件，不认 SecretStorage。扩展把 API key 存在编辑器的 SecretStorage 里，CLI 读不到，只能用 providers.json 里的 apiKey，或者 apiKeyEnv 指向的环境变量；
  2. 改完配置不用重启。交互模式里敲 /reload 就会重读 providers.json，当前模型被删了也会当场提示回落到了哪个。

本地回环端点（Ollama / llama.cpp / vLLM）不用配 key，--list-models 里 key=yes 那列只是方便你确认远端 provider 的 key 到位没有。

两种用法：一次性任务与交互对话

一次性任务最常见：给一句任务描述，跑完退出。

交互对话更像一个常驻助手：不带任务描述、且终端是真 TTY 时进入 REPL，每行一个问题，历史按 8 轮 / 12000 字符带进下一轮。

这里有个刻意的设计：管道 / 重定向 / CI 里不会进 REPL。没有「下一行提问」这回事，所以直接打印帮助并以退出码 2 结束。--json 同理，只属于一次性任务，交互模式不接受。

三档模式：默认只读

CLI 默认是 plan，不是 agent。这是个安全默认值：不写文件、不执行写命令，只调研、出计划。

参数 模式 能做什么
默认 / --plan plan 只读调研，产出「目标 / 现状 / 步骤 / 验证方式 / 风险」
--explore explore 只读调研，独立工具集与独立系统提示，跑完直接给结论，不再派子代理
--agent agent 完整 agent，可派子代理；必须再配 --apply 才真正放开写

--apply 只对 agent 生效。plan 不会因为你加了 --apply 就自动变成 agent；--explore 本来就是只读，加了也没用。想一步到位：

只读是两道闸：写文件的工具根本没注册，模型想调也调不到；run_command 还会逐段检查，写入类命令、重定向、命令替换直接拒绝并回一句原因。第二道是启发式检查，不是操作系统级沙箱——这一点和扩展面板里一样。

还有一个容易忽略的差异：CLI 没有审阅 / diff UI。加了 --apply 之后，写操作执行完就打印结果，没有「逐 hunk 保留 / 撤销」那套流程。所以在终端里放开写之前，最好先 --plan 看一眼，或者确保工作区在 git 里。

输出约定：stdout 是结果，stderr 是过程

这个约定让 CLI 特别适合接管道：

  • stdout：只有结果正文，流式写入；
  • stderr：spinner、工具调用、用量、todo、子代理进度，全走这边。

退出码也分了层：模型正常收尾是 0；超时 / 轮数用尽 / 被取消 / 报错是 1；参数或内部错误是 2。脚本里判断「这轮到底跑完没有」不用去解析文本。

不想看颜色和 spinner 就加 --no-tui；CI / 管道环境会自动退回纯文本，不用手动关。

交互模式里的斜杠命令

REPL 里以 / 开头的命令不跑模型、不消耗 token：

命令 作用
/help 查看帮助
/mode <plan|explore|agent> 切模式；加 --apply 一步打开写权限
/apply [on|off] 单独切写权限（agent 模式才真正放开写）
/model [<key>] 查看 / 切换模型，没配 key 的会标 key=NO
/reload 重读 ~/.luban/providers.json
/thinking [on|off] 思考内容实时显示还是折叠
/clear 清空对话记忆
/gamepad [raw|off] 测试手柄按键（只回显，不注入）
/exit 退出（Ctrl-D 也行）

提示符本身也在传递状态：luban(plan) 是只读，luban(agent*) 那个星号表示写已经放开。一眼就能看出这轮会不会落盘。

几个用起来才知道的细节

Ctrl-C 的语义。一轮正在跑时按 Ctrl-C，取消的是当前这一轮，不是退出进程；回到提示符再按才退出（退出码 130）。交互模式下这一点很重要——取消完还能接着问下一条。

思考过程默认折叠。模型思考时只在 spinner 上累计字数，想看全文加 --show-thinking，或在 REPL 里 /thinking on。默认不刷屏，是因为终端里思考内容混进正文会很难读。

限额。--max-rounds 控制模型请求轮数（默认走设置 / 100），--max-minutes 控制墙钟分钟（默认 15）。长任务可以放宽，脚本里则建议收紧，避免卡死。

工作目录。--root / -C 指定工作目录，默认 process.cwd()。@文件 引用、search_code 的索引范围都跟着它走。

班班。CLI 内置了一个 ASCII 小木匠「班班」，脸会跟着模式变：plan 是方框（尺子），explore 带问号，agent 常态，写放开时换成眯眼使劲。luban --mascot 可以单独看它的表情设计稿。看起来像彩蛋，其实是状态信号——一瞥就知道当前在哪档模式。

手柄（仅 macOS）。--gamepad 在交互对话里接管手柄：十字键 / 左摇杆选择，A 提交，B 取消，LB/RB 切模式，LT/RT 切模型。第一次启动会用 xcrun 编译一个小工具。算是「躺在椅子上让 agent 干活」的奇怪需求，但它真的能用。

和编辑器面板怎么分工

我的用法是：

  • 想清楚要做什么：用 luban --plan，只读、快、还能把计划重定向成文件；
  • 要逐 hunk 审阅：回编辑器面板，diff 和「保留这块 / 撤销这块」都在那边；
  • 无头 / 远程 / 批处理：用 CLI 一次性任务 + --json，脚本里判断退出码；
  • 长时间对话：本地用面板，SSH 用 luban REPL。

也要知道它的边界：CLI 里没有语言服务器，read_lints 读不到真实诊断（扩展会补一句「未读到诊断」）；没有编辑器，#selection 这类基于选区的引用自然也不存在；写操作没有审阅队列，落地即生效。它是「同一个 agent 的无头入口」，不是面板的完全等价替代。

小结

Luban CLI 的价值不在于「又做了一个命令行工具」，而在于把面板里的 agent 能力原样搬到了没有编辑器的地方：

  • 默认 plan 只读，--apply 才动手；
  • stdout 只放结果，stderr 放过程，天然适合管道和脚本；
  • --json + 分层退出码，机器可读；
  • REPL 里 /mode /apply /model /reload 随时调整，不用重启。

如果你已经装了 Luban 扩展，可以直接 npm i -g @luban-code/luban-code 试试；没装过的话，先在终端里跑一条 luban --plan "看看这个项目在做什么"，也算是对「无头 agent」最轻量的一次体验。
