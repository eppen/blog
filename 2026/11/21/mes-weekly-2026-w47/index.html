MES 2026 年第 47 周工作小结

发表于2026-11-21|更新于2026-11-21
|浏览量:

本周（11/16–11/21，共 44 条提交：master 24 条、feature/dispatching-eos-workflow 分支 20 条尚未合入）触达 240 个文件、约 +1.46 万 / -1.2 千行。主线只有一条——把调度指令真正接进 EOS 原生工作流，围绕它铺开的是审批人表达式、审批进度组件、审批组独立模块；其余是 EOS 工作流设计器合入 master、跨应用错误汇总、交接班 Word 导出细修和 POI 5 升级。改动集中在 mes-dispatching（78 个文件）、mes-workflow（57）、mes-operation（22）、mes-security（17）。

一、调度指令接入 EOS 原生工作流（主线，仍在分支）

这一块占了本周近一半工作量，从「单据怎么拆」一路做到「审批进度怎么显示」：

  • 单据拆分：事业部指令 / 计划调度部指令拆成两个 EOS 单据，MES 侧实体回退到原来的旧三表；配套脚本一并入库——eos_dispatching_instruction_split_views.sql、split_djdy / split_xmdy 视图、add_eos_columns，外加 no_ddl_plan.md 与 view_gate_check.md 两份方案/核验说明，先保证「不动 DDL 也能切」
  • 引擎切换：调度工作流改用 EOS nwf，开关置为 enabled: true；旧版 Flowable 定义同时留档作对照，方便回退
  • 审批人表达式：runsql + uf_get_wf_spyh 两级取人落地，SQL 放在 mes-nwf/doc/nwf_uf_wf_spyh.sql、nwf_uf_wf_spyh_expr_func.sql；两份 BPMN（事业部指令审批、计划调度部指令审批）与 nwf_processtype_dispatching.sql 注册脚本入库
  • 审批进度组件：新增 NwfFlowProgressService / Impl 与通用前端组件 nwf-flow-progress.js（337 行）/ .css（141 行），六个调度单据页面（事业部/计划调度部 × 编辑、待审批、已完成）统一接入，顺手删掉原来各页面重复的 132 行状态拼装逻辑
  • 列表体验：待审批状态下拉补「提交中」，状态筛选真正生效；待审批 / 已完成列表默认按 ID 倒序，新数据不再被挤到末页

二、EOS 工作流设计器增强并合入 master

feature/eos-nwf-graph-design 周五合入 master（+1300 行量级）：

  • AI 增量改图协议：设计器与 AI 之间改成按 ops 增量提交，不再整图覆盖，落盘走新写的 NwfGraphOpsApplier，配单测兜底
  • 拓扑编辑增强：拓扑变化后自动清理失效诊断（stale diagnostics pruning），画布不会残留已经对不上的提示
  • 打包 xml 同步修正，避免新增类没进包

三、审批组独立成模块（mes-workflow-approval）

从流程节点里的零散配置，抽成独立模块，39 个文件 +4000 行量级：

  • 三层结构：审批组类型 / 审批组 / 审批组成员，controller–dao–entity–service 齐套，配 4 个页面与对应 JS（含类型选择弹层）
  • 唯一键调整：审批组编码从全局唯一改为「部门 + 编码」，并给出 wf_approval_group_uk_migrate.sql 迁移脚本
  • 脚本齐备：表结构、菜单、种子数据三份 SQL（wf_approval_group_tables / _menu / _seed）与 README 一并入库
  • 顺手一处体验修正：角色/用户分组树改为同层按拼音排序、未分组置顶（CategoryTreeSortUtils + 单测）

四、EOS 菜单树节点详情（mes-security-eos）

  • 树节点选中后可看详情：EOS 侧角色、用户授权（含授权来源）+ 该节点关联的 MES 菜单授权
  • 新增 EosTreeNodeDetailService / Impl 与三个 DTO，11 个文件 +1418 行，含单测
  • eostree.js 同时补了「打开方式」选项，节点可以按不同入口打开

五、日志管理：跨应用错误汇总（errorSummary）

  • mes-core 定义 SPI JobFailureLogProvider，mes-quartz 侧用 QuartzJobFailureLogProvider 实现，定时任务失败能被统一收集
  • 日志管理页新增跨应用错误汇总视图，SysLogFileServiceImpl 主体 +543 行，前后端与使用说明同步补齐
  • 两侧都带单测（206 行 / 118 行），后续其它应用接新 provider 即可扩展

六、交接班与 Word 导出（mes-operation）

  • 班次时间：Word 导出按班次计算班次时间起止时段，展示格式统一为 yyyy年MM月dd日HH:mm — yyyy年MM月dd日HH:mm，占位符一并补齐
  • 单元格边距：新增 DocxTableCellMarginUtil（含单测），给导出表格补最小上下边距，多行内容不再贴着上下边框；页面上下边距统一 112 dxa
  • 填报列表：新增日志模版树，默认按「日志日期 + id」倒排
  • 页面：编辑页限制最大宽度，宽屏下不再拉满

七、报表与基础设施

  • 报表定时：新增「下载模版」动作，配权限 SQL rptschedule_download_perm.sql 与菜单项；模板处理与日期选择一并增强
  • POI 升级：4.1.2 → 5.2.5（feature/poi-5-upgrade 合入 master，19 个文件），父 POM 统一版本，mes-core / mes-plan / mes-report 三处适配，实施方案另存 doc/POI-5.2.5升级实施方案.md
  • 构建与仓库：修正打包 xml；.gitignore 忽略本地临时 SQL 导出、SQL 方言脚本与 jqgrid-fork 产物目录

八、事业部指令区域选择弹层

  • areaselect 页面从 mes-web 移到 mes-factory，修掉弹层 404，并修复双击选行
  • 事业部下拉列表无数据：在 mes-factory 侧新增本模块事业部接口，不再跨模块取数
