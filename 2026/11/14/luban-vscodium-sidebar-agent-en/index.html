I Put an AI Coding Agent in the VSCodium Sidebar and Let It Run the Tests Itself

发表于2026-11-14|更新于2026-11-14|Tech
|浏览量:

Luban is a VS Code / VSCodium extension that puts a coding agent in the sidebar: it reads and writes files in your workspace, runs commands, uses browser to look at pages and computer to drive the desktop to verify its own work, then reports back to you.

This is an updated take on “Meet Luban: a Coding Agent in the VSCodium Sidebar“ — that post covered what it is and how I used it on an MES project. Since then three modes, the browser / computer tools and the plugin system have landed, and they deserve a post of their own. The command-line face of the same thing has its own post, “Meet Luban CLI: a Coding Agent in the Terminal“.

1. Local models first

Most AI coding tools go through a third-party API key, so requests are relayed through the vendor’s servers. That breaks local models in two different ways. First, the network path doesn’t work: Ollama / llama.cpp / vLLM on localhost simply can’t be reached, so you end up tunneling the service onto the public internet — your code still leaves the machine. Second, the token budget isn’t there: a small-window model (4k / 8k) may connect but can’t actually run an agent, because the fixed overhead eats the window first — system prompt plus tool definitions alone run 3k+ tokens, leaving no room for code on the first turn.

Luban is designed around local models on both counts.

It connects. Requests go out from the extension process directly, with no intermediary service and no telemetry. Point the config at http://127.0.0.1:11434/v1 and you’re done — a loopback address doesn’t even need a key. Switching models means editing a JSON block; any OpenAI-compatible endpoint works: DeepSeek in the cloud, Ollama, llama.cpp or vLLM locally. API keys live in the editor’s SecretStorage and are never written to disk.

It runs. Several concrete things keep the fixed overhead down:

  • The tool layer is tiered by context window. Below 16k you get the “small-window tier”: tools drop from 20 to 17 and the fixed cost falls from 3.8k to about 2.2k tokens.
  • Message layout is aligned for prefix caching; from the second turn you typically see 95%+ cache hits.
  • Every turn shows input / output / cache hits / context usage / request count right under the answer.
  • The tool loop’s real constraints are the context window and wall-clock time, with a loop detector added; the turn cap is only a safety valve (200 by default, configurable). Forty-odd settings are editable, and there’s a local ledger plus a usage dashboard.

2. Three modes: Plan / Agent / Chat

A dropdown at the bottom of the panel switches between three modes; Shift+Tab cycles through them.

  • Plan: the file-writing tools are not registered at all — it isn’t talked out of writing via a prompt, it literally can’t call them; run_command additionally goes through a per-segment read-only check. Research results land in a Markdown plan (goal / current state / steps / how to verify / risks) that opens automatically; edit it, click “execute this plan”, and it follows your edited version.
  • Agent: the full toolset. Read and write files, run commands to verify itself, long tests via start / poll so the loop isn’t blocked, multi-step tasks tracked with todo_write, and ask_question with clickable options when a real decision needs a human.
  • Chat: not a single tool, pure Q&A, not one tool call issued. Use it for “what does this code do” or “why this error”; a message containing @web searches first, then answers.

3. Review happens in the editor

After writing a file, Luban opens a native diff right in the editor: the title bar has “keep all / revert all”, CodeLens on both sides lets you decide each hunk separately, and the chat area keeps only a one-line summary. Edits go through “read the original → precise local replacement”.

4. One kernel, several ways in

The same tool loop can be driven from elsewhere:

  • CLI: npm i -g @luban-code/luban-code, then luban --plan "survey the src/ directory", luban --agent --apply "create utils.js and write tests", with a unified diff to confirm before each write to disk;
  • ACP: in Zed / JetBrains, use Luban as the agent itself — body text, thinking and tool cards all render natively;
  • MCP / plugins / skills: tools from a local stdio MCP server join the same tool loop (mcp__<server>__<tool>), local plugins join it with a pl__ prefix, and SKILL.md files under ~/.claude/skills and ~/.cursor/skills can be read too.

A few smaller things along the way: a hand-written Markdown preview (code highlighting, local images by relative path, scrolling with the editor), and a status-bar line like (o.o) run_command npm test — the little carpenter “Banban”‘s face plus the current state, turning into -_- on its own after idling too long.

5. Two hands: browser use, computer use

Both tools are off by default, which is why many people install it and never notice them.

  • browser (looking at pages): starts a headless instance of your local Chrome / Edge, then open → snapshot (an accessibility-tree outline, far cheaper in tokens than raw HTML) → screenshot / console / network. In Agent mode it can also click / type / scroll for real. No Playwright — the CDP layer is a hand-written minimal WebSocket, zero new dependencies; a temporary profile, so it never carries your login state; and there is no “run arbitrary JS” entry point, the three interaction actions go through fixed channels. You can open a preview panel that shows a screenshot of the page the agent is working on once a second — same instance, not a second one.
  • computer (driving the desktop): screenshot, read text off the screen, list windows, plus click / double-click / drag / scroll / type / key combos. On macOS it uses screencapture + CGEvent + Vision; on Windows an embedded C# helper — likewise no third-party dependencies. Linux has a path too, via the system’s xdotool and ffmpeg, with OCR through tesseract-ocr; under a Wayland session only XWayland apps can be driven. Coordinates are logical screen points; if the image was downscaled the tool reports the ratio, and you can pass imageCoords to have it converted. It asks once before touching your mouse and keyboard for the first time.

Two boundaries are written in code, not in a prompt: computer is withheld entirely in Plan mode, and browser allows its read-only actions but not its interactive ones — clicking and typing change external state, so you can’t open the whole tool just because some of its actions are read-only. Cost needs restraint too: a full-screen desktop screenshot is about 3000 tokens, so if run_command and browser can do the job, leave the desktop alone.

Reading and writing files, running commands, looking at pages, driving the desktop — the extension does all of these itself. One layer further out are plugins.

6. Plugins

Three kinds are supported:

  • Tool plugins: the sample demo plugin provides now (local time and timezone) and disk_free (free disk space).
  • Theme plugins: once installed, pick the color scheme in the panel. theme-midnight and theme-sakura ship ready-made.
  • Skills: a SKILL.md instruction sheet the model reads and follows.

Plugin repository: eppen/luban-plugins. You can use the existing plugins and themes as references to build your own.

Install location: globally at ~/.luban/plugins/ or per-workspace at <workspace>/.luban/plugins/ (a same-named project-level one overrides the global), or luban plugin add <name> to install from the index.

A note: tool plugins run code, so they’re off by default (luban.plugins.enabled), with one prompt on first load and one on directory content changes; theme plugins execute nothing and aren’t affected by that switch.

Install

  • Search Luban in the VS Code Marketplace / Open VSX extension panel
  • Or grab the VSIX from GitHub Releases, then in the extension panel ⋯ → Install from VSIX

Prerequisites: VS Code / VSCodium 1.104+, and a provider configured in ~/.luban/providers.json.

If you want to try it, a good first task is this prompt:
Create utils.js exporting debounce(fn, ms) and throttle(fn, ms), then test both behaviors with node.
