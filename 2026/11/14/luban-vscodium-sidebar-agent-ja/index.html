AI コーディングエージェントを VSCodium のサイドバーに組み込んで、テストまで自分で走らせさせた

发表于2026-11-14|更新于2026-11-14|Tech
|浏览量:

Luban は VS Code / VSCodium の拡張機能で、コーディングエージェントをサイドバーに置きます。ワークスペースのファイルを読み書きし、コマンドを実行し、browser でページを見て computer でデスクトップを操作して自分の仕事を検証し、最後に結果をまとめて報告します。

これは「Luban を知る：VSCodium のサイドバーに組み込まれたコーディングエージェント」の更新版です。前回はそれが何か、MES プロジェクトでどう使ったかを書きました。それ以降、3 つのモード、browser / computer の 2 つのツール、プラグインシステムが入ったので、改めて独立した記事にします。コマンドラインの顔には別の記事「Luban CLI を知る：コーディングエージェントをターミナルへ」があります。

1. ローカルモデルを先に考える

ほとんどの AI コーディングツールはサードパーティの API キーを使い、リクエストはベンダーのサーバーを経由します。これはローカルモデルに対して 2 つの別々の問題を起こします。1 つ目はネットワーク経路が通らないこと。localhost の Ollama / llama.cpp / vLLM にはそもそも届かないので、トンネルでサービスを公開ネットに晒すことになり、コードは結局外に出ます。2 つ目はトークン予算が足りないこと。小さいコンテキストウィンドウのモデル（4k / 8k）は接続できてもエージェントを動かせません。固定コストが先にウィンドウを食い尽くします。システムプロンプトとツール定義だけで 3k+ トークンになるので、最初のターンにコードを置く場所が残りません。

Luban はこの 2 点についてローカルモデル前提で設計しています。

つながる。 リクエストは拡張機能のプロセスから直接出ます。中継サービスもテレメトリもありません。設定に http://127.0.0.1:11434/v1 と書けばよく、ループバックアドレスならキーすら不要です。モデルを変えるのは JSON の一か所を書き換えるだけ。OpenAI 互換のエンドポイントなら何でも受け付けます。クラウドの DeepSeek、ローカルの Ollama、llama.cpp、vLLM。API キーはエディタの SecretStorage に保存され、ディスクには書かれません。

動く。 固定コストを抑えるために具体的にいくつかやっています。

  • ツール層はコンテキストウィンドウで段階分け。16k 未満だと「小ウィンドウ段」に入り、ツールは 20 個から 17 個に減り、固定コストは 3.8k から約 2.2k トークンに下がります。
  • メッセージの並びはプレフィックスキャッシュに合わせてあり、2 ターン目以降は通常 95%+ のキャッシュヒットが得られます。
  • 毎ターンの回答の下に、入力 / 出力 / キャッシュヒット / コンテキスト使用量 / リクエスト数をそのまま表示します。
  • ツールループの本当の制約はコンテキストウィンドウと経過時間で、無限ループ検出を追加しました。ターン数上限は安全弁にすぎません（デフォルト 200、設定可）。40 項目以上の設定が変更でき、ローカルの台帳と使用量ダッシュボードもあります。

2. 3 つのモード：Plan / Agent / Chat

パネル下部のドロップダウンで 3 つのモードを切り替えます。Shift+Tab で 3 つを順に循環します。

  • Plan：ファイルを書くツールがそもそも登録されていません。プロンプトで書くなと説得するのではなく、呼び出せないのです。run_command はさらに一段ずつの読み取り専用チェックを通ります。調査結果は Markdown の計画（目標 / 現状 / 手順 / 検証方法 / リスク）になり、自動で開きます。編集して「この計画を実行」を押すと、編集後の版に沿って進みます。
  • Agent：ツール一式。ファイルの読み書き、自分で検証するためのコマンド実行、長いテストは start / poll でループを塞がない、複数ステップのタスクは todo_write で追跡、本当に人間の判断が要る分岐では ask_question で選択肢を出します。
  • Chat：ツールを 1 つも渡しません。純粋な質疑応答で、ツール呼び出しは 1 回も出しません。「このコードは何をしているか」「このエラーはなぜ起きるか」に使います。メッセージに @web があれば先に検索してから答えます。

3. レビューはエディタの中で

ファイルを書き終えると、Luban はエディタでネイティブの diff を開きます。タイトルバーに「すべて保持 / すべて取り消し」、両側に hunk ごとの CodeLens があって一つずつ決められ、チャット欄には要約が 1 行残るだけです。変更は「原文を読む → 正確な部分置換」で行います。

4. 1 つのカーネル、複数の入り口

同じツールループは別の場所からも駆動できます。

  • CLI：npm i -g @luban-code/luban-code、luban --plan "src/ の構成を調査"、luban --agent --apply "utils.js を作ってテストを書く"。ディスクに書く前に毎回 unified diff で確認します。
  • ACP：Zed / JetBrains で Luban をそのままエージェントとして使えます。本文、思考、ツールカードがすべてネイティブに描画されます。
  • MCP / プラグイン / スキル：ローカルの stdio MCP サーバーのツールは同じツールループに合流します（mcp__<server>__<tool>）。ローカルプラグインは pl__ 接頭辞で同じループに入り、~/.claude/skills や ~/.cursor/skills の SKILL.md も読めます。

他にも小さな機能がいくつか。自作の Markdown プレビュー（コードハイライト、相対パスのローカル画像、エディタに合わせたスクロール）と、ステータスバーの (o.o) run_command npm test という 1 行。小さな大工「バンバン」の顔と現在の状態で、放置が長くなると勝手に -_- になります。

5. 二本の手：browser use、computer use

2 つのツールはどちらもデフォルトでオフなので、インストールしただけでは気づかない人が多いです。

  • browser（ページを見る）：ローカルの Chrome / Edge でヘッドレスインスタンスを起動し、open → snapshot（アクセシビリティツリーの概要で、生の HTML よりかなりトークンを節約できます）→ screenshot / console / network。Agent モードなら click / type / scroll で実際に操作もできます。Playwright は使わず、CDP は手書きの最小限の WebSocket で、依存関係はゼロ増です。一時プロファイルなのでログイン状態は持ちません。「任意の JS を実行」する入口もなく、3 つの操作は固定の経路を通ります。プレビューパネルを開けば、エージェントが操作中のページのスクリーンショットを毎秒 1 枚見られます。同じインスタンスで、別に起動するわけではありません。
  • computer（デスクトップを動かす）：スクリーンショット、画面の文字の読み取り、ウィンドウの一覧、さらにクリック / ダブルクリック / ドラッグ / スクロール / 入力 / キー組み合わせ。macOS は screencapture + CGEvent + Vision、Windows は内蔵の C# helper で、どちらもサードパーティ依存なし。Linux もあり、システムの xdotool と ffmpeg を使い、OCR は tesseract-ocr です。Wayland セッションでは XWayland アプリしか操作できません。座標は「画面の論理点」で、画像が縮小されていれば倍率を報告し、imageCoords を渡せば換算してくれます。初めてマウスとキーボードを動かす前に 1 回だけ確認します。

2 つの境界はプロンプトではなくコードに書いてあります。computer は Plan モードでは丸ごと渡しません。browser は読み取り専用の操作は使えて、操作を伴うものは渡しません。クリックと入力は外部の状態を変えるので、一部が読み取り専用だからといって丸ごと許可するわけにはいきません。コストにも節度が要ります。全画面のデスクトップスクリーンショットは約 3000 トークンです。run_command と browser で済むならデスクトップには触れない。

ファイルの読み書き、コマンド実行、ページを見る、デスクトップを動かす。これらはすべて拡張機能が自分でやっています。もう一層外に広げたものがプラグインです。

6. プラグイン

3 種類に対応しています。

  • ツールプラグイン：サンプルの demo プラグインの機能。now はローカルの時刻とタイムゾーン、disk_free はディスクの空き容量を報告します。
  • テーマプラグイン：インストールするとパネルで配色を選べます。theme-midnight と theme-sakura が用意されています。
  • スキル：SKILL.md の説明書で、モデルが読んでそれに従います。

プラグインリポジトリ：eppen/luban-plugins。 既存のプラグインやテーマを参考に、自分のプラグインやテーマを作れます。

インストール場所：グローバルは ~/.luban/plugins/、ワークスペース単位は <workspace>/.luban/plugins/（同名ならプロジェクト側がグローバルを上書き）。luban plugin add <名前> でインデックスから入れることもできます。

注意：ツールプラグインはコードを実行するので、デフォルトではオフです（luban.plugins.enabled）。初回読み込み時とディレクトリ内容の変化時にそれぞれ 1 回確認します。テーマプラグインは何も実行しないので、このスイッチの影響を受けません。

インストール

  • VS Code Marketplace / Open VSX の拡張パネルで Luban を検索
  • または GitHub Releases から VSIX をダウンロードし、拡張パネルの ⋯ → Install from VSIX

前提条件：VS Code / VSCodium 1.104+、および ~/.luban/providers.json にプロバイダを設定済みであること。

試すなら、最初のタスクとしてこのプロンプトをおすすめします。
utils.js を作り、debounce(fn, ms) と throttle(fn, ms) をエクスポートし、node で両者の挙動をテストする。
