我把 AI 编码助手塞进了 VSCodium 侧边栏，还让它自己跑测试

发表于2026-11-14|更新于2026-11-14|技术
|浏览量:

Luban 是 VS Code / VSCodium 的一个扩展，把编码 agent 放在侧边栏里：它读写工作区里的文件、跑命令，会用 browser 看页面、computer 动桌面自己验证，最后汇总给你。

这篇是《认识 Luban：嵌在 VSCodium 侧边栏里的编码 Agent》的更新版——那篇写了它是什么、我在 MES 项目里怎么用它；这段时间补上来的三档模式、browser / computer 两个工具、插件系统，值得单独讲一遍。命令行那副面孔另有一篇《认识 Luban CLI：把编码 Agent 搬进终端》。

一、支持本地模型

大多数 AI 编码工具走第三方 API key，请求要在厂商服务器中转。这对本地模型有两个不同的问题：一是网络路径不通，localhost 上的 Ollama / llama.cpp / vLLM 根本打不通，只能靠隧道把服务暴露成公网——代码照样出网；二是 token 预算不够，小窗口模型（4k / 8k）即使连上了也跑不动 agent，固定开销先把窗口吃完了——系统提示加工具定义动辄 3k+ token，第一轮就没地方放代码。

Luban 在这两件事上都按本地模型来设计。

连得上。 请求由扩展进程直接发出，不经过任何中间服务，也不带遥测。配置里写 http://127.0.0.1:11434/v1 就行，回环地址连 key 都不用填。要换模型就换一段 JSON，任何 OpenAI 兼容端点都能接：云端的 DeepSeek，本地的 Ollama、llama.cpp、vLLM。API key 存在编辑器的 SecretStorage 里，不落盘。

跑得动。 为省固定开销做了几件具体的事：

  • 工具层按窗口分档，窗口小于 16k 时进入「小窗口档」，工具从 20 个收到 17 个，固定开销从 3.8k 降到约 2.2k token；
  • 消息排布对齐前缀缓存，第二轮起通常能拿到 95%+ 的缓存命中；
  • 每轮回答下面直接显示输入 / 输出 / 缓存命中 / 上下文占用 / 请求数；
  • 工具循环的主约束是上下文窗口和墙钟，加了死循环检测，轮数上限只当安全阀（默认 200，可配）；四十多项配置都能改，另有一份本地账本和用量看板。

二、三种模式：Plan / Agent / Chat

面板底部的下拉框切三个模式，快捷键 Shift+Tab 在三个模式间循环切换。

  • Plan（制定计划）：写文件的工具根本没有注册——不是靠提示词劝它别写，是它调不到；run_command 还要再过一道逐段只读校验。调研结果落成一份 Markdown 计划（目标 / 现状 / 步骤 / 验证方式 / 风险）并自动打开，你改完点「执行这个计划」，它就按你改后的版本走。
  • Agent（修改文件）：全套工具。读写文件、跑命令自己验证、长测用 start / poll 不堵住循环、多步任务用 todo_write 跟踪、遇到真正需要人拍板的分叉就用 ask_question 给你几个可点选项。
  • Chat（只是聊天）：一个工具都不给，纯问答，不发出一条工具调用。「这段代码什么意思」「这个报错什么原因」用它，消息里带 @web 会先搜再答。

三、审阅在编辑器里

写完一个文件，Luban 直接在编辑器里开原生 diff，标题栏是「全部保留 / 全部撤销」，两侧有逐块 CodeLens 让你对每个 hunk 单独决定，聊天区只留一行摘要。修改走「读原文 → 精确局部替换」。

四、一个内核，多访问入口

同一套工具循环还能被别处驱动：

  • CLI：npm i -g @luban-code/luban-code，luban --plan "调研 src/ 目录结构"，luban --agent --apply "新建 utils.js 并写测试"，落盘前逐次给 unified diff 确认；
  • ACP：Zed / JetBrains 里把 Luban 当自己的 agent 用，正文、思考、工具卡片都是原生渲染；
  • MCP / 插件 / 技能：本地 stdio MCP server 的工具并进同一个工具循环（mcp__<server>__<tool>），本地插件用 pl__ 前缀进同一个循环，~/.claude/skills、~/.cursor/skills 里的 SKILL.md 也能被读。

顺带还有几个小功能：自己写的 Markdown 预览（代码高亮、本地图片按相对路径显示、跟着编辑器滚动），以及状态栏一行 (o.o) run_command npm test —— 小木匠「班班」的脸加当前状态，挂机久了它自己变成 -_-。

五、两只手：browser use，computer use

两个工具默认都关着，所以很多人装完没发现有这两个工具。

  • browser（看页面）：用本机 Chrome / Edge 起无头实例，open → snapshot（取可访问性树大纲，比裸 HTML 省一大截 token）→ screenshot / console / network。Agent 模式下还能 click / type / scroll 真去点。没引 Playwright，CDP 是手写的极简 WebSocket，零新增依赖；临时 profile，不带你的登录态；也没有「执行任意 JS」的入口，三个交互动作走固定通道。可以开个预览面板，每秒看一张 agent 正在操作的页面截图——同一个实例，不是另开一个。
  • computer（动桌面）：截屏、读屏上文字、列窗口，以及点击 / 双击 / 拖动 / 滚动 / 输入 / 组合键。macOS 走 screencapture + CGEvent + Vision，Windows 走内嵌的 C# helper，一样没有第三方依赖；Linux 也有一套，靠系统的 xdotool 与 ffmpeg，OCR 用 tesseract-ocr，Wayland 会话下只能操作 XWayland 应用。坐标是「屏幕逻辑点」，图被压过会回报倍率，也可以传 imageCoords 让工具换算。第一次动鼠标键盘前问你一次。

两条边界写在代码里，不在提示词里：computer 在 Plan 模式下整支不给，browser 的只读动作能用、交互动作不给——点击和输入会改外部状态，不能因为其中几个动作只读就整支放行。成本上也得克制：一张全屏桌面截图约 3000 token，能用 run_command 和 browser 解决的就别动桌面。

读写文件、跑命令、看页面、动桌面，这些都是扩展自己在做。再往外扩一层，才是插件。

六、插件

现在支持三类：

  • 工具插件：示例插件 demo 的功能：now 报本机时间和时区，disk_free 报磁盘剩余空间。
  • 主题插件：装完在面板里选配色。现成有 theme-midnight、theme-sakura。
  • 技能：一份 SKILL.md 说明书，模型读了照着做。

插件仓库：eppen/luban-plugins。 可以参考已有插件、主题制作自己的插件、主题。

安装位置：全局 ~/.luban/plugins/ 或 <工作区>/.luban/plugins/（同名时项目级覆盖全局），也可以 luban plugin add <名字> 从索引里装。

提醒：工具插件跑的是代码，所以默认关着（luban.plugins.enabled），首次加载和目录内容变化各问一次；主题插件不执行任何东西，不受这个开关影响。

安装

  • VS Code 市场 / Open VSX 扩展面板搜 Luban
  • VSIX 从 GitHub Releases 下载，扩展面板 ⋯ → Install from VSIX

前置条件：VS Code / VSCodium 1.104+，并在 ~/.luban/providers.json 里配好一个 provider。

想试的话建议第一个任务，提示词：
新建 utils.js，导出 debounce(fn, ms) 和 throttle(fn, ms)，然后用 node 测一下两者行为。
