apple/container 实测：能替掉 OrbStack 吗？我装了又卸了

发表于2026-11-17|更新于2026-11-17|技术
|浏览量:

Apple 在 2025 年开源了 apple/container，一个用 Swift 写的 macOS 容器运行时：不装 Docker Desktop、不装 OrbStack，纯 Apple 自己的 Virtualization.framework 跑容器。官网那句「run OCI containers natively on macOS」确实诱人——尤其是对已经对第三方虚拟机方案产生依赖疲劳的人。于是我在这台 M 系列 Mac 上装了一份，跟在用的 OrbStack 正面比了一轮。

结论先说：它确实能用，但替代不了 OrbStack，测完我把它卸了。

先说清楚它是什么

很多人第一次看到 apple/container 都以为它是「官方版 Docker」，其实架构完全不同：

OrbStack / Docker Desktop apple/container
虚拟化 一个 Linux 虚拟机，所有容器共享内核 每个容器一个轻量虚拟机
隔离级别 进程级（共享内核） 虚拟机级
Docker API / socket ✅ 完整兼容 ❌ 没有 dockerd，没有兼容层
docker compose ✅ ❌ 完全没有
镜像格式 OCI OCI（也能用 Dockerfile 构建、推 registry）
K8s ✅ ✅（container k8s，较新版本才有）
费用 Docker Desktop 商用收费 / OrbStack 商用收费 Apache 2.0，完全免费

一容器一 VM 的代价是每个容器都要占一份虚拟机开销，收益是隔离级别高得多。而「没有 Docker API」这一条，直接判了一批工具的死刑：Testcontainers、IDE 里的 Docker 插件、Portainer、各种吃 docker.sock 的 CI 脚本，全部用不了。

  1. brew tap apple/apple 拉下来的 tap 里没有 container 这个 formula，得直接 brew install container（homebrew-core 里有），装到的是 1.7.1。

实测数据

环境：M 系列 Mac + macOS 27.0.1，对照组 OrbStack（docker CLI 指向 orbstack context）。测试镜像 alpine:latest，构建测试用一个两层 RUN + COPY 1MB 文件的 Dockerfile。

1. 启动：冷启动打平，热启动慢一倍

  • 完全冷启动（服务停掉再起）：container system start(1.65s) + 首次 run(3.31s) ≈ 4.96s；OrbStack 从停到首次 run ≈ 4.99s。基本没差别。
  • 热状态连续 5 次 run --rm alpine echo hi：
    • OrbStack：1.28 ~ 1.52s，均值 约 1.37s
    • apple/container：2.28 ~ 3.60s，均值 约 2.8s

热启动 container 慢了约 2 倍——这是一容器一 VM 的固有开销，每个容器都要拉起一个微型虚机。

2. 构建：这是它赢的地方

同一个 Dockerfile：

场景 apple/container OrbStack (docker)
首次构建 33.2s（含一次性拉 builder-shim，只发生一次） —
--no-cache 重建 2.2s 7.7s
缓存命中 1.8s 4.6s

两轮都比 docker 快 2 倍以上，大概得益于镜像层缓存直接落在 macOS 侧、不用穿虚拟机的文件系统。

3. 挂载 IO：没测完

原计划用 dd 往挂载卷写 200MB 测吞吐，测试文件生成后计划被中断，这一项没有数据，不编。真在意文件共享性能的话，OrbStack 的既有口碑一直不错，这也是我日常选它的主因之一。

结论：什么情况选谁

测完的判断很直接——

继续用 OrbStack 的理由：

  • 项目里有 docker-compose.yml：container 完全不支持，多容器编排得手搓脚本；
  • 工具链依赖 docker.sock / Docker API：Testcontainers、IDE 集成、CI 脚本，一律不可用；
  • 要 localhost 直通、稳定的容器 IP、成熟的文件共享：开发体验上 OrbStack 明显更省心。

apple/container 值得一用的场景：

  • 跑单个 Linux 容器、一次性验证环境，尤其需要虚拟机级隔离的实验；
  • 不想再依赖任何第三方虚拟机软件，只认 Apple 原生；
  • 要一个完全免费、Apache 2.0、纯开源的方案。

最终动作：按「不如就卸」的约定，我把它卸了——brew uninstall container + 清掉数据目录 + 删除测试镜像，回收约 2.3GB。系统校验无残留，OrbStack 运行正常。想再试一条命令就能回来：brew install container。

两者本可以共存（命令名不同：container 与 docker，socket 也不冲突），所以这不算「不推荐」，只是对我这种 compose + Docker API 重度依赖的日常开发流来说，替代关系不成立。Apple 这个项目更像一个给特定场景准备的原生运行时，而不是 Docker Desktop / OrbStack 的正面挑战者。
