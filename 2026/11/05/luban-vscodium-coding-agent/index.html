认识 Luban：嵌在 VSCodium 侧边栏里的编码 Agent

发表于2026-11-05|更新于2026-11-05
|浏览量:

最近在日常开发里一直在用一个嵌在 VSCodium 侧边栏里的编码 agent，名字叫 Luban（鲁班）。名字取自古代工匠，寓意很直白：一个帮你”干活”的工匠。这篇文章介绍一下它是什么、能做什么、以及我在 MES 项目里实际用它的方式。

它是什么

Luban 是一个嵌在 VSCodium 侧边栏里的编码 agent：

  • 底层模型可配置：由用户配置的 provider 决定，不绑定某一家模型；
  • 直接读写本机文件：不是”给你一段代码你自己贴”，而是直接在工作区里增删改文件；
  • 可以执行 shell 命令：写完代码能自己跑 mvn、node、git 验证，把真实输出作为结论依据；
  • 支持 MCP 外部工具：通过 mcp__<server>__<tool> 形式接入外部能力，比如数据库查询。

它和”聊天式 AI 助手”最大的区别在于：它默认以完成任务为目标，而不是以回答问题为目标。你给它一个任务，它会自己拆步骤、查代码、改文件、跑验证，最后用中文汇报改了哪些文件、做了什么、验证结果如何。

核心能力

1. 代码检索：先定位，再精读

大仓库里直接全量扫文件是灾难。Luban 内置了分层检索工具：

场景 工具
按内容关键词 / 标识符找 search_code（BM25 词法索引，最省 token）
按文件名找文件 glob（如 **/*config*）
正则 / 精确串匹配 grep（对标 ripgrep）

定位到文件与行号后再 read_file 精读。这套”先索引后精读”的流程，让它在一个上万文件的 MES 仓库里也能快速找到目标代码。

2. 文件修改：局部替换优先

  • 修改已有文件前必须先读原文，再用 replace_in_file 做局部替换（容忍行尾 CRLF/LF、缩进差异）；
  • 跨多个文件的重构 / 批量改名用 apply_patch，一次提交多文件增 / 改 / 删，全成功才落盘，任一文件校验失败则整体不写；
  • 改完代码后可以 read_lints 读语言服务器报的 error / warning，自己发现类型错 / 语法错，而不是等用户贴报错。

3. 命令执行：短命令同步，长构建异步

  • 预计 60 秒内的验证用 run_command 同步执行；
  • 长测 / 长构建（如全量 Maven install）用 run_command_start 后台启动，再 run_command_poll 看进度，取消用 run_command_stop。

这意味着”改完代码 → 自己编译 → 自己看报错 → 再修”这个闭环可以在一次对话里完成。

4. MCP 外部工具：以数据库为例

Luban 接入了两个 SQL Server MCP server：

  • mssql-mesdata：MES 业务数据库
  • mssql-messys：MES 系统管理库

每个 server 提供 14 个工具：查表结构（describe_table）、只读查询（read_data）、执行计划（explain_query）、表画像（profile_table）、依赖分析（inspect_dependencies）等。

配合项目规则，Luban 对数据库的写操作有严格约束：非 Docker 环境禁止自动执行写库 SQL，只做只读 SELECT 排查、改仓库内 .sql 文件、给出完整可复制的执行命令。数据库口令放在 .luban/mcp.json（已 gitignore），模板是 .luban/mcp.json.example。

5. 技能（Skills）：把重复流程沉淀成文档

Luban 支持”技能”：一个目录 + 一份 SKILL.md，把某类任务的完整流程写成文档，真正要用时先读 SKILL.md 全文再按步骤执行。

在 MES 项目里已经沉淀了一批技能：

技能 用途
mes-maven-pack 全量 Maven install + 打 WAR
mes-hot-patch 制作 Tomcat exploded 热补丁包
mes-log-analyze 分析服务器下载的 MES 运行日志，提取 ERROR/WARN、堆栈聚类
mes-count-loc 统计 Java / JS / HTML 有效代码行数
mes-flowable-publish 把本地 BPMN 导入 Flowable Modeler 并发布
mes-git-release-tag 在 master 打 annotated release tag 并推送
mes-work-summary-blog 从 git 历史归纳周报/月报，生成 Hexo 文章并发布到个人博客
mes-xss-pentest 在本地 Docker MES 上做 XSS 渗透/回归验证

技能的价值在于：流程、命令、坑点都固化在文档里，agent 每次执行都按同一套标准走，不靠”记忆”。

6. 任务跟踪与交互

  • todo_write：任务拆成多步时维护任务清单，同时只能有一个 in_progress，完成一项再标下一项；
  • ask_question：出现实质分叉、需要人拍板时，给出可点选项等用户选择，而不是把开放问题写进长文末尾；
  • web_search / web_fetch：需要外部最新信息（版本号、官方文档、报错原因）时可以联网查，引用时标注来源。

项目级规则：CLAUDE.md

Luban 会读取项目根目录的 CLAUDE.md（与 .cursor/rules/、.claude/rules/ 内容同源）。MES 项目里这份规则覆盖了：

  1. 数据库安全（最高优先级）：非 Docker 环境禁止自动写库；存储过程必须交付完整文件，禁止补丁式改写；
  2. 后端约定：Service 继承 BaseService<T, ID> 基类；Jackson 时间格式统一 GMT+8 / yyyy-MM-dd HH:mm:ss；
  3. 前端约定：改 JS 必须升 ?v= 版本号；CRUD 列表默认带导出；操作提示统一走 common.js 封装；
  4. 部署约定：Docker 镜像未挂载 resources，改前端后必须重新 mvn install + docker compose up -d --build + restart nginx；
  5. Git 约定：合并必须 --no-ff；执行过 git 操作后必须回显实际命令；
  6. 语言约定：所有回答、解释、计划、总结一律使用中文（简体），代码标识符与报错原文保持原文。

这些规则让 agent 的行为和项目规范对齐，而不是每次都要口头交代。

实际使用感受

在 MES 项目里，Luban 承担的主要工作：

  • 日常开发：前后端 CRUD、导出、页面布局，按项目规则一次做齐；
  • 排查问题：连数据库只读查询 + 日志分析技能，定位线上问题；
  • 发布运维：打 release tag、做热补丁包、Maven 打包；
  • 文档与博客：从 git 历史归纳周报/月报，自动生成 Hexo 文章并发布到 eppencn.com——这篇文章本身就是它写的。

几点体会：

  1. 规则文件是杠杆。把项目约定写进 CLAUDE.md 和技能文档后，agent 的输出质量提升非常明显，返工变少；
  2. 验证闭环很关键。能自己跑命令、自己看 lint 的 agent，和只能”给建议”的助手是两种生产力；
  3. 安全边界要显式声明。数据库写操作、git push 这类动作，规则里写死”仅当用户明确要求”，比事后补救可靠得多。

小结

Luban 是一个”嵌在编辑器里、能读写文件、能跑命令、能连数据库、能按技能文档干活”的编码 agent。名字取自鲁班，定位也很鲁班：不是设计师，是工匠——把活干完，把验证结果摆出来。

如果你也在用 VSCodium / VS Code 做日常开发，可以关注一下侧边栏 agent + MCP + 技能文档这套组合，它正在把”AI 辅助编码”从”问答”推进到”交付”。
